# Pathora — персональный маршрут поступления

**Рабочий продукт:** https://danabelgibek.github.io/PathoraAI/
**Репозиторий:** https://github.com/danabelgibek/PathoraAI
**Вход не требуется** — приложение открывается без регистрации и без оплаты.

LOCUS Startup Hackathon 2026, кейс 02 «Персональный маршрут поступления».

---

## 1. Задача

Абитуриенту нужен маршрут, а не ещё один список университетов. Поступление за рубеж —
это десятки связанных решений: направление, страна, университет, языковой экзамен,
признание аттестата, документы, дедлайны, стипендии, виза. Информация разрознена по
сайтам вузов на разных языках, рекомендации в интернете слишком общие, и абитуриент не
понимает двух вещей: **что подходит именно ему** и **что делать прямо сейчас**.

**Целевая аудитория:** ученики 10–11 классов, выпускники школ и студенты колледжей из
Казахстана и Центральной Азии, поступающие на бакалавриат за рубеж.

## 2. Решение

Pathora проводит пользователя по одному связному сценарию из шести шагов:

| Шаг | Что получает пользователь |
| --- | --- |
| 1. Вход | Объяснение ценности и ожидаемого результата |
| 2. Анкета | 6 шагов: статус обучения, успеваемость, цель, страны и бюджет, язык и сроки, проверка |
| 3. Диагностика | Индекс готовности 0–100 с разбором по 4 параметрам, сильные стороны, ограничения, точки роста |
| 4. Подбор | Программы с блоком «почему подходит» из 5 аргументов, разделённые на «в выбранных странах» и «альтернативы» |
| 5. Сравнение | Таблица из 12 параметров, сопоставленных с анкетой |
| 6. Маршрут | 6 этапов с задачами, дедлайнами, объяснением «зачем» и ссылками на источники |

Сквозь весь путь работает **«Следующий шаг»** — одна выделенная задача, выбранная по
приоритету и дедлайну, с кнопкой «Отметить выполненным». Прогресс сохраняется.

### Что делает продукт действительно персональным

Изменение любого ключевого ответа в анкете перестраивает результат:

- **Страна** — программы делятся на «в выбранных странах» и «альтернативы»; если по стране
  данных нет, сервис прямо об этом сообщает, а не подменяет молча.
- **Языковой экзамен** — IELTS, TOEFL iBT и Duolingo сравниваются с порогом вуза **в своей
  шкале**, с пересчётом в эквивалент IELTS для общей оценки.
- **Средний балл** — шкалы 5.0 / 4.0 / 100 нормализуются к пятибалльной, в которой заданы
  пороги вузов.
- **Бюджет** — влияет на баллы соответствия, тексты аргументов и фильтр «в рамках бюджета».
- **Уровень образования и ступень** — меняют состав задач маршрута (какие выписки нужны,
  нужен ли Studienkolleg / Foundation).
- **Целевой семестр** — от даты начала занятий пересчитываются **все** дедлайны маршрута.
- **Целевой вуз** — маршрут меняет платформу подачи, языковые требования, стипендии и
  страновые шаги (Uni-Assist, Studielink, Universitaly, TOL, Numerus Fixus).

Уведомления тоже генерируются из текущего состояния профиля и маршрута, а не хранятся
готовым списком.

## 3. Стек

- **React 19** + **TypeScript** (`strict: true`)
- **Vite 8** — сборка и dev-сервер
- **Tailwind CSS 4** — единая дизайн-система через токены в `src/lib/ui.ts`
- **lucide-react** — иконки
- **localStorage** — сохранение состояния (регламент кейса допускает локальное хранение
  вместо сложного бэкенда, если полный путь работает)
- **GitHub Actions + GitHub Pages** — деплой при каждом пуше в `main`

Внешних API, серверов и баз данных нет: приложение полностью статическое.

## 4. Архитектура

```
index.html
src/
  main.tsx                  точка входа
  App.tsx                   состояние, маршрутизация между экранами, сохранение
  types.ts                  все доменные типы
  data/
    universities.ts         демо-база программ (8 шт.) с источниками
    countries.ts            страны + сколько программ по каждой есть в базе
    demoProfile.ts          профиль по умолчанию и 4 готовых сценария
  lib/
    scoring.ts              нормализация GPA и языковых шкал (IELTS/TOEFL/Duolingo)
    intake.ts               целевой семестр → пересчёт дедлайнов
    matching.ts             подбор программ и генерация аргументов «почему подходит»
    diagnosis.ts            индекс готовности, сильные стороны, ограничения
    roadmap.ts              построение маршрута, «следующий шаг», ближайшие дедлайны
    notifications.ts        уведомления из текущего состояния
    ui.ts                   дизайн-токены: цвета состояний, подписи, форматирование
    storage.ts              хук сохранения в localStorage
  components/               Header, UniversityDetailModal, DemoDataNotice, ErrorBoundary
  views/                    7 экранов пользовательского пути
```

**Ключевой принцип:** вся логика вычислений отделена от отрисовки и живёт в `src/lib/`.
Каждый аргумент, который видит пользователь, порождается тем же кодом, который начисляет
баллы, — оценки без объяснения появиться не может.

**Как считается соответствие (`src/lib/matching.ts`):** базовые 50 баллов, затем
направление (+14 / +7 / −12), страна (+18), бюджет (+12 / +4 / −14), язык (+12 / +8 / −6 /
−18), успеваемость (+10 / +7 / −4 / −14), приоритет стипендии (+4). Результат
ограничивается диапазоном 20–97.

## 5. Запуск

Нужен Node.js 20+.

```bash
npm install
npm run dev        # http://localhost:5173
```

```bash
npm run build      # production-сборка в dist/
npm run preview    # локальный просмотр сборки
npm run typecheck  # проверка типов
```

> При локальном запуске `vite.config.ts` содержит `base` для GitHub Pages. На dev-сервере
> это не мешает: Vite сам обслуживает приложение по этому пути.

## 6. Тестовый сценарий для жюри

1. Откройте рабочую ссылку. На главной нажмите **«Заполнить анкету»**.
2. Пройдите 6 шагов. На шаге 1 в правом верхнем углу есть выпадающий список
   **«Готовый сценарий»** — он заполняет анкету одним из четырёх наборов данных.
3. На экране диагностики проверьте индекс готовности, разбор по параметрам, сильные
   стороны и ограничения.
4. Перейдите к подбору. У каждой карточки раскрыт блок **«Почему подходит твоему профилю»**
   из пяти аргументов и ссылка на официальный источник.
5. Добавьте две программы **«К сравнению»** и откройте сравнение.
6. Нажмите **«Построить маршрут»** — откроется план с выделенным «Следующим шагом».
7. Отметьте шаг выполненным: прогресс пересчитается в шапке, на дашборде и в маршруте.
8. **Перезагрузите страницу** — экран, анкета, прогресс, сравнение и избранное сохранятся.

### Проверка реакции на изменение данных

Вернитесь в анкету и измените любой из ответов:

| Что изменить | Что должно произойти |
| --- | --- |
| Страны → только Италия | Раздел «В выбранных странах» покажет 1 программу, остальные уйдут в «Альтернативы» |
| Страны → Канада | Появится честное предупреждение: программ по этой стране в базе нет |
| Экзамен → TOEFL 105 | Пороги пересчитаются в шкале TOEFL, появится эквивалент IELTS |
| Экзамен → «не сдан» | В маршрут добавятся два критичных шага: запись на экзамен и сдача |
| Бюджет → $4 000 | Изменятся баллы, тексты аргументов и финансовая часть диагностики |
| Направление → «История искусств» | Сервис сообщит, что таких программ в базе нет, и пометит несовпадение в каждой карточке |
| Целевой вуз → RWTH Aachen | В маршруте появится обязательный немецкий B2/C1 вместо базового A1–A2 |
| Целевой семестр → весна 2027 | Все дедлайны маршрута пересчитаются, часть шагов станет критичной |
| Ступень → подготовительный год | В маршруте появится шаг выбора Foundation / Studienkolleg |

Сбросить всё к исходному состоянию — ссылка **«Сбросить данные и начать заново»** в подвале.

## 9. AI, API и внешние сервисы

**В продукте не используются LLM, генеративные модели и внешние API.**

Это осознанное решение: регламент кейса прямо разрешает rule-based логику, а для задачи
«объяснить, почему программа подходит» детерминированные правила дают то, чего не даёт
генерация, — **проверяемость**. Каждый аргумент однозначно выводится из конкретного
сравнения числа из анкеты с числом из требований вуза, одинаков при одинаковых входных
данных и не может быть выдуман моделью.

Для честности: **название «AI Admission Navigator» из первой версии убрано** — сервис
называется просто Pathora и нигде не заявляет об использовании AI.

AI-инструменты использовались **при разработке** (написание и ревью кода) — это разрешено
регламентом. Вся логика кейса написана в период хакатона.

## 11. Техническая справка

- **Модели:** не используются.
- **API и внешние сервисы:** нет. Единственный внешний запрос — шрифты Google Fonts.
- **Библиотеки:** react, react-dom, lucide-react (runtime); vite, typescript, tailwindcss,
  @tailwindcss/vite, @vitejs/plugin-react (сборка).
- **Данные:** локальный статический набор в `src/data/`, 8 программ, источники выше.
- **Методы проверки результата:**
  - `npm run typecheck` — строгая проверка типов (`strict`, `noUnusedLocals`);
  - `npm run build` — сборка, выполняется в CI при каждом пуше;
  - ручной прогон тестового сценария из раздела 6 на десктопе и на мобильном (375 px);
  - проверка реакции на изменение каждого ключевого ответа анкеты по таблице из раздела 6.
- **Меры безопасности:** секретов и ключей в репозитории нет, `.env` не используется;
  приложение не собирает и не передаёт персональные данные — всё, что вводит пользователь,
  остаётся в его браузере в `localStorage` и стирается кнопкой сброса; внешние ссылки
  открываются с `rel="noopener noreferrer"`; ошибки отрисовки перехватываются
  `ErrorBoundary` и не роняют приложение.

## 12. Известные ограничения

1. **База из 8 программ** — только инженерные и IT-направления в 4 странах (Германия,
   Нидерланды, Южная Корея, Италия). Продукт честно сообщает об этом, когда запрос выходит
   за охват базы, а не подменяет результат.
2. **Данные статические и демонстрационные.** Автоматической синхронизации с сайтами вузов
   нет; актуальность гарантирована только на дату сверки.
3. **Индекс готовности — не прогноз зачисления.** Это взвешенная оценка по правилам
   Pathora, помогающая увидеть слабое место, а не вероятность поступления.
4. **Нет бэкенда и аккаунтов.** Данные живут в браузере: на другом устройстве профиля не
   будет, очистка данных сайта его удалит.
5. **Один язык интерфейса** — русский.
6. **Эквиваленты языковых шкал приблизительны.** Используются официальные таблицы
   сопоставления ETS и Duolingo; отдельные вузы применяют собственные таблицы.
7. **Нет автотестов** — проверка ручная по сценарию из раздела 6.
